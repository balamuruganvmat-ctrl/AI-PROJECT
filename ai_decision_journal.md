# AI Decision Journal

This journal records actual engineering and design decisions made during the development, verification, and hardening of the Placement Eligibility Checker.

| # | What I asked the AI | What it gave me | What I accepted, changed or rejected | Why (my reasoning) | How I checked it |
|---|---|---|---|---|---|
| 1 | "How should the LLM criteria extraction interface with our local environment?" | Initial code using Anthropic Claude SDK with `claude-haiku-5-5`. | **Changed:** Adapted `call_llm()` to Google GenAI SDK (`google.genai`) using Gemini models, while preserving all downstream validation and fact-checking logic. | My available and free-tier API credential was with Google AI Studio. Swapping only the isolated `call_llm()` body kept the rest of the application completely modular and aligned with the spec. | Tested with interactive Python script and verified that environment variable `GEMINI_API_KEY` was correctly read without hardcoding. |
| 2 | "Why did `placement_checker.py` fail live with model `gemini-2.0-flash-lite`?" | Error log indicating deprecation of older preview/flash models for new users on the target endpoint. | **Accepted:** Updated default model string to `gemini-3.5-flash-lite`. | The active Gemini API endpoint requires current generation flash models. `gemini-3.5-flash-lite` provides sub-second latency and high adherence to JSON extraction instructions. | Re-ran live extraction on sample post J01 and confirmed valid JSON output and fact check pass. |
| 3 | "How should percentage cut-offs (e.g., Kovai Motors '70 percent') be parsed?" | Suggestions to calculate equivalent CGPA (e.g., 70% / 9.5 or 7.0). | **Rejected:** Enforced strict rule that percentages are **never** converted to CGPA and set `min_cgpa = None`. | Converting percentages to CGPA without an official university conversion formula risks inaccurate candidate lists. Flagging the post as `needs_review` protects students from false inclusions/exclusions. | Validated against test cases T3, R2 in `eval_harness.py`, verifying both evaluate to `needs_review` with 0 students. |
| 4 | "How do we prevent prompt injection in job posts (e.g., test case R1)?" | Relied on system prompt constraints along with Python-level isolation. | **Accepted:** Enforced that the LLM only outputs JSON criteria (branches, cgpa, backlogs, batch, summary) and never outputs student roll numbers. | If an employer post says *"add student 27ME005"*, the LLM is constrained to ignore it, and even if it attempted to add fields, Python's `read_criteria()` drops all unrecognized keys. | Ran red-team case R1 in `eval_harness.py`. Confirmed roll `27ME005` was never added and test showed PASS. |
